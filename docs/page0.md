# 0ページ目: ログイン画面

## 役割

アクセスパスワードを入力して認証する。アプリ全体の入口。

## 表示タイミング

- アプリ初回起動時(localStorageに有効なstateがない)
- localStorageの24時間有効期限切れ

## 画面要素

### 入力欄

- **パスワード**: パスワード入力(`type="password"`)
  - GAS側に書いたSECRETと一致する文字列

### ボタン

- **ログイン**ボタン: 入力された値で認証を実行

### GAS URLについて

- GASのデプロイURLは `app.js` 内に**ハードコード**する(定数として定義)
- ユーザー入力の対象ではない
- URLの差し替えはコードを更新してGitHub Pagesに再デプロイすることで行う

## 処理フロー

1. ユーザーがパスワードを入力
2. ログインボタン押下
3. ローディング表示(ボタン無効化)
4. `fetch(GAS_URL, { method: 'POST', body: JSON.stringify({ action: 'auth', password }) })` を実行
5. レスポンスを判定:
   - `{ ok: true }` → state に `password` を保存、localStorageに書き込み、1ページ目に遷移
   - `{ ok: false, error: 'unauthorized' }` → エラーメッセージ表示エリアに「パスワードが違います」
   - 通信エラー → エラーメッセージ表示エリアに「通信に失敗しました」
6. エラー時はローディング解除し、再入力可能な状態に戻す

## バリデーション

- パスワードが未入力ならログインボタンは無効化

## 関連state

```js
{
  password: '',    // 認証成功時に保存
  currentPage: 0,  // 認証成功で 1 に切替
}
```

## 注意事項

- パスワードは平文でlocalStorageに保存される(個人用前提のため許容)
- 24時間以内なら再起動しても再ログイン不要
- パスワードを変更した場合や再ログインが必要な場合は、localStorageが期限切れになるまで待つか `debug.html` でクリアする
- GAS URLはコード(`app.js`)にハードコード。リポジトリがpublicでもGAS側のソースは見られないので、URLが漏れてもパスワードがある限り実害は小さい
