# 3ページ目: 場代・飲み代の精算

## 役割

場代と飲み代を入力し、4人で割り勘して各人の負担額を確定する。同じUIを場代→飲み代の順で2回使う。

## 表示タイミング

- 2ページ目「ゲーム終了」直後(場代モードで開始)
- レジューム時に `currentPage === 3` だった場合(`phase` の値で場代/飲み代を判別)

## モード

- `phase: 'venue'` … 場代入力中
- `phase: 'drink'` … 飲み代入力中
- 場代の「金額確定」で `phase` を `drink` に切替、入力欄リセット
- 飲み代の「金額確定」後も同じ画面に留まり、再入力可能(2軒目、3軒目への対応)
- 最終的な「終了」処理は持たない。ユーザーが必要なくなったら画面を閉じるだけでOK
- localStorageは24時間で自動的に消える

## 画面構成

### 上部: 局結果一覧

- 2ページ目の局一覧と同じ表示(デフォルト倍率適用後モード)
- 確認用、編集不可

### 下部: 精算入力

#### 入力欄

- **場代総額** (or 飲み代総額): 数値入力
- **丸め単位**: セグメント切替(1円 / 10円 / 100円)
- **支払者**: 4人から1人をラジオ選択

#### 精算テーブル

| プレイヤー | 単純割 | 端数調整 | 合計 | 支払い |
|---|---|---|---|---|
| プ1 | -2,200 | 0 | -2,200 | |
| プ2 | -2,200 | 0 | -2,200 | ✓ |
| プ3 | -2,200 | 0 | -2,200 | |
| プ4 | -2,200 | 0 | -2,200 | |
| 合計 | | 200 | -8,800 | |

#### 各列の仕様

- **単純割**:
  - 編集不可
  - 計算式: `-(総額 / 4)` を「丸め単位」で絶対値が小さくなる方向に丸めた値
  - 例: 9000円、丸め単位10円 → 9000/4=2250 → -2250 → 10円単位で-2200
  - 丸め単位が変わったら即座に再計算

- **端数調整**:
  - ユーザーが各プレイヤーごとに手動入力(初期値0)
  - 数値入力(`inputmode="numeric"`、負の数も入力可能)

- **合計**:
  - `単純割 + 端数調整`
  - 編集不可

- **支払い**:
  - ラジオボタン(1人だけ選択)
  - 出力時、支払者は他3人から回収する形で記録

#### 合計行

- **端数調整合計の表示**: 「不足額」を表示
  - 計算: `総額 + 単純割合計 + 端数調整合計`
  - 0になると合計列の合計が `-(総額)` と一致 → 金額確定可能
  - 例: 場代9000、単純割合計-8800 → 不足200(調整合計が0の場合)
  - プ1の端数調整に-200を入力すると不足が0になり、総合計が-9000になる
- **総合計**: 合計列の合計をリアルタイム表示

### ボタン

- **金額確定**:
  - 有効化条件: `総合計 === -(総額)` かつ支払者が選択済み
  - 場代モード時: phaseをdrinkに切替、入力欄リセット
  - 飲み代モード時: 入力内容を保存し、入力欄をリセットして同じ画面に留まる(次の飲み代を入力可能)

## 処理フロー

### 入力中

1. ユーザーが総額を入力 → 単純割を自動計算して表示
2. 丸め単位を変更 → 単純割を再計算
3. ユーザーが端数調整に調整値を入力 → 合計と総合計をリアルタイム更新
4. 不足額が0になり、支払者が選ばれたら金額確定ボタンが有効化

### 金額確定(場代モード)

1. ボタン押下
2. stateの `venue` に確定値を保存
3. localStorage更新
4. GASに `action: 'save'` で送信
5. `phase` を `drink` に切替
6. 入力欄をリセット(端数調整はすべて0、総額・支払者は空、丸め単位はデフォルトの1円)
7. 画面ヘッダの表示を「場代 → 飲み代」に変更

### 金額確定(飲み代モード)

1. ボタン押下
2. stateの `drinks` 配列に確定値を1件追加
3. localStorage更新
4. GASに `action: 'save'` で送信
5. 入力欄をリセット(同じ画面に留まる、次の飲み代を入力可能)
6. 失敗時はエラー表示してリトライ可能に(state上は確定前の状態に戻す)

## 関連state

```js
{
  venue: {
    total: 9000,
    payerIndex: 1,        // 0-3
    roundUnit: 10,
    base: [-2200, -2200, -2200, -2200],
    adjust: [0, 0, 0, 0],
  },
  drinks: [               // 配列。複数軒分の入力に対応
    {
      total: 10000,
      payerIndex: 3,
      roundUnit: 10,
      base: [-2500, -2500, -2500, -2500],
      adjust: [0, 0, 0, 0],
    },
    // 2軒目以降があれば追加される
  ],
  phase: 'venue',         // 'venue' | 'drink'
  currentPage: 3,
}
```

## バリデーション

- 総額が正の整数
- 支払者が選択されている
- 不足額が0(総合計が -(総額) と一致)
- すべて満たすと金額確定ボタンが有効

## エラー処理

- `save` 失敗時:
  - phaseの切替や `drinks` への追加は行わず、エラー表示してリトライ可能に
  - localStorageには変更前の状態が残っているので入力内容は失われない

## 注意事項

- 場代と飲み代は本質的に同じ処理なのでUIコンポーネントを共通化して使い回す
- 丸め単位は場代/飲み代で独立(モード切替時にリセット)
- 支払者も場代/飲み代で別々に選べる(同じ人とは限らない)
- 飲み代は何軒分でも入力可能。それぞれ確定するごとに `drinks` 配列に追加される
- 「終了」ボタンは無し。ユーザーが入力を終えたらブラウザを閉じるだけでOK
- localStorageは24時間で自動クリアされる
