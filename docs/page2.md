# 2ページ目: 局ごとの素点入力

## 役割

各局の4人の素点と倍率を入力し、ウマ・勝点を自動計算して局として記録する。確定済みの局は下部に一覧表示する。

## 表示タイミング

- 1ページ目「ゲーム開始」直後
- レジューム時に `currentPage === 2` だった場合

## 画面構成

### 上部: 入力エリア

- 表形式で4プレイヤー分の行
- 列: プレイヤー名 / 得点(素点入力) / ウマ(自動) / 勝点(自動)
- 倍率の入力欄(局ごとに変わる)
- **得点確定**ボタン

### 下部: 局一覧

- 確定済みの全局を縦に表示
- 列: 局番号 / プ1 / プ2 / プ3 / プ4 / 横合計 / 倍率
- **切り替え**ボタンで2モード切替:
  - **倍率適用後モード**(デフォルト): 各値 = ウマ込み勝点 × 倍率
  - **素点モード**: 各値 = ウマ込み勝点(倍率適用前)
- 素点モード時は最下段に各プレイヤーの合計行を表示
- **ゲーム終了**ボタン → 3ページ目へ

## 計算ロジック

### 入力

- 4人の素点 (`raw[0..3]`)
- ウマ1 (`uma1`)、ウマ2 (`uma2`) ※1ページ目で設定済み
- 倍率 (`multiplier`)

### 手順

1. **順位決定**: 素点の降順で1〜4位
2. **千点単位への丸め(五捨六入)**:
   - 各素点を1000で割り、五捨六入で整数化
3. **2〜4位の勝点(ウマ込み前)**:
   - `勝点 = 丸め後の点数 - 30`
4. **1位の勝点(ウマ込み前)**:
   - `勝点 = -(2位 + 3位 + 4位の勝点合計)`
   - 4人の合計を必ず0にするための調整(端数が1位に寄る)
5. **ウマ加算**:
   - 1位: `+uma1`、2位: `+uma2`、3位: `-uma2`、4位: `-uma1`
6. **検算**: 4人の勝点合計が0になることを確認

### 五捨六入

四捨五入の麻雀流変形(`.5`以下は切り捨て、`.6`以上は切り上げ)。

```js
function gosharokunyu(value) {
  return Math.floor(value + 0.4);
}

const rounded = gosharokunyu(score / 1000);
```

例: 9.5→9, 9.6→10, 27.5→27, 27.6→28

### 計算例

入力: プ1=12000, プ2=9800, プ3=27500, プ4=50700, ウマ1=10, ウマ2=5, 倍率=3

- 順位: プ4(1位) > プ3(2位) > プ1(3位) > プ2(4位)
- 五捨六入: プ1=12, プ2=10, プ3=27, プ4=51
- 2〜4位の勝点(ウマ込み前): プ3=-3, プ1=-18, プ2=-20
- 1位の勝点(ウマ込み前): プ4 = -(-3 + -18 + -20) = +41
- ウマ加算後: プ4=+51, プ3=+2, プ1=-23, プ2=-30 (合計0)
- 倍率適用後: プ4=+153, プ3=+6, プ1=-69, プ2=-90 (合計0)

## 素点入力の自動計算挙動

### フォーカスイン時

- ウマ・勝点の自動計算結果をクリア(表示を空にする)
- 素点欄自体はそのまま(クリアしない)

### フォーカスアウト時

空欄の数を確認して動作を分岐:

- **空欄が1つ**: その欄を4人目として `100000 - 他3人の合計` で自動計算して表示 → 4人揃ったのでウマ・勝点も自動計算してリアルタイム表示
- **空欄が0または2以上**: 何もしない

### 素点修正の流れ(例)

1. 一度4人確定済みの状態でプ1の欄をタップ(フォーカスイン) → ウマ・勝点クリア
2. プ1の値を修正して別の欄へ(フォーカスアウト) → 空欄0なので何もしない、ウマ・勝点は空のまま
3. プ3の欄の値を消してフォーカスアウト → 空欄が1つ(プ3)なのでプ3を `100000 - 他3人の合計` で再計算 → ウマ・勝点も再計算

### 得点確定ボタンの有効化条件

- 4人の素点がすべて埋まっている(空欄0)
- ウマ・勝点の自動計算が完了している
- 倍率が入力されている

## 関連state

```js
{
  rounds: [
    {
      points: [-23, -30, 2, 51],  // ウマ込み勝点(4人分)
      multiplier: 3,               // 倍率
      // 素点(raw)は保存しない。表示に不要なため。
      // 倍率適用後の値は points[i] * multiplier でその都度計算する
    },
    // ...複数局
  ],
  currentPage: 2,  // ゲーム終了で 3 に切替
}
```

## 処理フロー(得点確定ボタン押下)

1. バリデーション:
   - 4人すべての素点が埋まっているか
   - 倍率が正の整数か
2. ロジックに従って計算 → `rounds` 配列に追加
3. localStorage更新
4. GASに `action: 'save'` で送信
5. 上部入力エリアをクリア(倍率は前回値を保持)
6. 下部の局一覧を更新

- 「得点確定」: 4人の素点と倍率がすべて入力されたら有効
- 「ゲーム終了」: `rounds.length >= 1` で有効
- 「切り替え」: 常に有効

## エラー処理

- `save` リクエスト失敗時:
  - localStorageには保存済みなので画面表示は維持
  - 「保存に失敗しました。同期ボタンで再試行してください」と通知
  - 局一覧表示は更新済みなので、ユーザーは続行可能

## 注意事項

- 局数は可変(最低1局〜上限なし)
- 一度確定した局の編集・削除はアプリ上では行わない(スプレッド側で直接修正)
- 倍率のデフォルト値は前回入力値か3が無難
