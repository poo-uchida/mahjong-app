# 麻雀成績入力アプリ 要件定義

## 1. 概要

iPhone Safariで利用する個人用Webアプリ。1日分の麻雀(4人打ち)の成績を入力し、最終結果をGoogleスプレッドシートにフォーマットして書き出す。

## 2. 利用環境・対象ユーザー

- 利用デバイス: iPhone Safari (縦画面)
- 利用者: 自分のみ(認証不要)
- 利用シーン: 麻雀の対局中〜終了後にリアルタイムで入力
- 1日完結: 過去の履歴を跨ぐ機能は持たない(1回起動=1日分)

## 3. アーキテクチャ

### 構成

- **フロントエンド**: GitHub Pagesで静的ホスティング
- **バックエンド**: Google Apps Script (GAS) のWebアプリ (`doPost`)
- **データストア**: Googleスプレッドシート

### 通信

- フロント → GAS は `fetch` でPOST
- CORS回避のため `Content-Type: text/plain` でJSON文字列を送る
- GAS側はWebアプリとしてデプロイ(「全員」アクセス可、実行権限は自分)

### GAS側を分離する理由

GASだけで完結させるとHTML上部にGoogle警告バーが表示され、iframe化によりiPhoneでビューポートが崩れて横幅が制御できないため。

### リポジトリ構成

フロントとGASを同一リポジトリで管理する。GASは [clasp](https://github.com/google/clasp) を使ってローカル管理。

```
mahjong-app/
├── frontend/        # GitHub Pagesで公開
│   ├── index.html
│   ├── app.js
│   └── style.css
├── gas/             # claspで管理するGAS側
│   ├── .clasp.json
│   ├── appsscript.json
│   └── Code.js
├── docs/
│   └── spec.md
└── README.md
```

claspのセットアップ手順:

1. `npm install -g @google/clasp`
2. `clasp login` でGoogleアカウント認証
3. 既存GASプロジェクトを `clasp clone <scriptId>` で取得、または `clasp create` で新規作成
4. ローカル編集後 `clasp push` で反映、`clasp deploy` でWebアプリとしてデプロイ

### リポジトリ公開設定

- **publicリポジトリで運用可**(無料のGitHub Pagesを使う前提)
- 機密情報をコードに埋め込まない作りにする:
  - GASのデプロイURL: 初回起動時に設定画面から入力 → localStorageに保存
  - スプレッドシートIDも同様、GAS側に持たせる場合は `gas/` に `.gitignore` で除外する設定ファイルを置く
- privateリポジトリで運用したい場合は GitHub Pro 以上のプランが必要

## 4. UIライブラリ

- **Bootstrap 5** を採用
- 理由: フォーム・テーブルが標準で揃いiPhone表示も無難。個人用で素早く作るのに向く
- CDN読み込みでビルド工程不要

## 5. ページ構成

全3ページ。SPA的に1ファイル内で表示切替してもよいし、ページ遷移でもよい。

### 5.1 1ページ目: 設定

入力項目:
- 日付 (yyyy/mm/dd)
- 参加者4名の名前 (プレイヤー1〜4)
- ウマ1 (1位⇔4位の点差、デフォルト10)
- ウマ2 (2位⇔3位の点差、デフォルト5)

ボタン:
- 「ゲーム開始」→ 2ページ目へ

### 5.2 2ページ目: 局ごとの素点入力

#### 上部: 入力エリア

- 表形式で4プレイヤー分の行を表示
- 各行に「得点(素点)」「ウマ」「勝点」の列
- **ユーザーが入力するのは「得点(素点)」のみ**
- ウマと勝点は素点入力後に自動計算して表示
- 倍率の入力欄(局ごとに変わる)
- 「得点確定」ボタン → 1局として下部に追加

#### 下部: 局一覧表示

- 確定済みの全局を縦に並べて表示
- 列: 局番号 / プ1 / プ2 / プ3 / プ4 / 横合計 / 倍率
- 「切り替え」ボタンで2モードを切替:
  - **倍率適用後モード**(デフォルト): 各値 = 勝点 × 倍率
  - **素点モード**: 各値 = 入力した勝点そのまま
- 素点モード時は最下段に各プレイヤーの合計行を表示
- 「ゲーム終了」ボタン → 3ページ目へ

#### 計算ロジック (重要)

入力: 4人の素点、ウマ1、ウマ2、倍率

1. **順位決定**: 素点の降順で1〜4位を決める
2. **千点単位への丸め**(五捨六入):
   - 各素点を1000で割り、五捨六入(.6以上を繰り上げ、.5以下を切り捨て)で整数化
   - 例: 12000→12, 9800→10, 27500→27, 50700→51
3. **2〜4位の勝点(ウマ込み前)**:
   - `勝点 = 丸め後の点数 - 30`
4. **1位の勝点(ウマ込み前)**:
   - `勝点 = -(2位 + 3位 + 4位の勝点合計)`
   - これにより4人の合計が必ず0になる(端数を1位に寄せる仕様)
5. **ウマを加算**:
   - 1位: +ウマ1
   - 2位: +ウマ2
   - 3位: -ウマ2
   - 4位: -ウマ1
6. **検算**: 4人の勝点合計は必ず0

#### 五捨六入の定義

四捨五入の麻雀流変形。

- `.5` 以下は切り捨て
- `.6` 以上は切り上げ
- 例: 9.5→9, 9.6→10, 27.5→27, 27.6→28

実装イメージ(JavaScript):

```js
function gosharokunyu(value) {
  // 0.4を足してから切り捨てることで、.5以下は捨て、.6以上は繰り上げになる
  return Math.floor(value + 0.4);
}

// 呼び出し例
const rounded = gosharokunyu(score / 1000);
```

#### 計算例

入力: プ1=12000, プ2=9800, プ3=27500, プ4=50700, ウマ1=10, ウマ2=5, 倍率=3

- 順位: プ4(1位) > プ3(2位) > プ1(3位) > プ2(4位)
- 五捨六入: プ1=12, プ2=10, プ3=27, プ4=51
- 2〜4位の勝点(ウマ込み前): プ3=-3, プ1=-18, プ2=-20
- 1位の勝点(ウマ込み前): プ4 = -(-3 + -18 + -20) = +41
- ウマ加算後の勝点: プ4=+51, プ3=+2, プ1=-23, プ2=-30 (合計0)
- 倍率適用後: プ4=+153, プ3=+6, プ1=-69, プ2=-90 (合計0)

### 5.3 3ページ目: 場代・飲み代の精算

場代と飲み代は本質的に同じ処理なので、**同じUIを使い回す**。

- 起動時は「場代」モード
- 「金額確定」ボタンを押すと「飲み代」モードに切り替わる
- 飲み代の「金額確定」を押すと完了(スプレッドシート出力へ)

#### 上部: 局結果一覧

- 2ページ目下部と同じ表示(倍率適用後モード固定でよい)

#### 下部: 精算入力

レイアウト(列構成):

| プレイヤー | 単純割(C列) | 調整(D列) | 合計(E列) | 支払い |
|---|---|---|---|---|
| プ1 | -2,200 | 0 | -2,200 | |
| プ2 | -2,200 | 0 | -2,200 | ✓ |
| プ3 | -2,200 | 0 | -2,200 | |
| プ4 | -2,200 | 0 | -2,200 | |
| 合計 | | 200 | -8,800 | |

各列の仕様:

- **C列(単純割)**:
  - 編集不可
  - 計算式: `-(場代総額 / 4)` を「丸め単位」で丸めた値
  - 丸めは絶対値ベースで、各人が払う側なので「切り下げ」(=絶対値が小さくなる方向)
  - 例: 9000円、丸め単位10円 → 9000/4=2250 → -2250だが10円単位で丸めて-2200
  
- **D列(調整)**:
  - ユーザーが手動入力(初期値0)
  - 各プレイヤーごとに自由に増減

- **E列(合計)**:
  - `C列 + D列`
  - 編集不可

- **支払い列**:
  - ラジオボタン的に1人だけ選択可能(誰が一括で店に払ったか)
  - 出力時、支払者は他3人から回収する形になる

最下段の合計行:

- **C列合計**: 表示しない(or グレーアウト)
- **D列合計の表示**: 「不足額(=場代総額 - C列合計の絶対値の差分)」を表示
  - 例: 場代9000、C列合計-8800 → 不足200
  - ユーザーがD列に調整値を入れると、`不足 - D列調整合計` に変化
  - **0になったら金額確定ボタンが有効化**
- **E列合計**: C+Dの合計、場代総額(マイナス)と一致すべき

入力欄:
- 場代総額(初期値: 飲み代モード時は前回値や任意のデフォルト)
- 丸め単位 (1円 / 10円 / 100円のセグメント切替)
- 支払者選択

ボタン:
- 「金額確定」(E列合計と場代総額がマイナスで一致する時のみ有効)

#### モード切替

- 場代モードの「金額確定」→ 飲み代モードに切替(入力欄リセット)
- 飲み代モードの「金額確定」→ スプレッドシート出力処理

## 6. スプレッドシート出力

### 出力先

- **ゲーム開始時に毎回新規スプレッドシートを作成**する
- ファイル名: `yyyymmdd麻雀` (例: `20260503麻雀`)
- 作成は1ページ目「ゲーム開始」ボタン押下時にGAS側で実行 (`SpreadsheetApp.create`)
- 作成後のスプレッドシートIDをフロントに返却し、localStorageに保存
- 以降の `save` / `load` リクエストはこのIDを指定して操作

### 24時間制限との関係

- localStorageの有効期間は24時間
- 期限切れでlocalStorageが消えると、シートIDも失われる → 翌日以降は別の新規シートとして扱う
- 過去のシートにアクセスする手段はアプリには持たせない(必要ならGoogle Driveから直接開く)

### 出力フォーマット

参考: `https://docs.google.com/spreadsheets/d/1xVpgJpBNe5u_yKB_3j55DFT99TlgKuhgSzpUNFNkP08/`

レイアウト概要(列構成):

| 局 | プ1 | プ2 | プ3 | プ4 | 横軸合計 | 倍率 |
|---|---|---|---|---|---|---|

- 上段: 各局の素点(勝点)とその局の倍率
- 中段: 倍率適用後の値
- 麻雀合計行: 中段の縦合計
- 場代合計行: 各人の場代負担額
- 飲み代合計行: 各人の飲み代負担額
- 収支合計行: 麻雀合計 + 場代 + 飲み代

詳細フォーマットは元シートの構造に合わせる(実装時に元シートを参照して合わせ込む)。

## 8. GAS API仕様

GASのWebアプリは1つのエンドポイントで複数アクションを受け付ける。リクエストボディの `action` フィールドで処理を分岐。

### エンドポイント

`POST /` (Webアプリとしてデプロイされたdoc URL)

### アクション一覧

#### `action: 'create'` - 新規スプレッドシート作成

ゲーム開始時に呼び出す。`yyyymmdd麻雀` のファイル名でスプレッドシートを新規作成し、IDを返す。

リクエスト:
```json
{
  "action": "create",
  "date": "2026-05-03"
}
```

レスポンス:
```json
{
  "ok": true,
  "spreadsheetId": "1abc...",
  "sheetUrl": "https://docs.google.com/spreadsheets/d/1abc.../"
}
```

#### `action: 'save'` - 状態を書き込み

リクエスト:
```json
{
  "action": "save",
  "spreadsheetId": "1abc...",
  "data": {
    "date": "2026-05-03",
    "players": ["いけだ", "わたなべ", "きよし", "うちだ"],
    "uma1": 10,
    "uma2": 5,
    "rounds": [
      {
        "raw": [12000, 9800, 27500, 50700],
        "points": [-23, -30, 2, 51],
        "multiplier": 3
      }
    ],
    "venue": {
      "total": 9000,
      "payerIndex": 1,
      "amounts": [-2200, -2200, -2200, -2200]
    },
    "drink": {
      "total": 10000,
      "payerIndex": 3,
      "amounts": [-2500, -2500, -2500, -2500]
    }
  }
}
```

レスポンス:
```json
{ "ok": true }
```

#### `action: 'load'` - 状態を読み込み

リクエスト:
```json
{
  "action": "load",
  "spreadsheetId": "1abc..."
}
```

レスポンス: `save` の `data` と同じ構造を返す
```json
{ "ok": true, "data": { ... } }
```

### エラー時

```json
{ "ok": false, "error": "..." }
```

## 9. データ保存とレジューム

### 二重保存戦略

不慮の事故(画面リロード、Safariのタブ落ち、通信失敗など)でデータが失われないよう、ローカルとクラウドの両方に保存する。

#### ローカル保存 (localStorage)

- **保存タイミング**: 状態が変化するたびに自動保存(デバウンス500ms程度)
- **保存内容**: フロント内部の `state` オブジェクト全体 + 保存時刻 (`savedAt`) をJSON化
- **キー名**: 例 `mahjong-app-state`
- **有効期間**: 24時間
  - localStorage自体には有効期限機能がないため、保存時に `savedAt` (Date.now()) を一緒に格納
  - 読み込み時に `Date.now() - savedAt > 24時間` なら破棄
- **クリアタイミング**:
  - 飲み代の「金額確定」(=最終確定)成功後
  - 読み込み時に有効期間切れを検知した時

実装イメージ:

```js
const STORAGE_KEY = 'mahjong-app-state';
const ONE_DAY_MS = 24 * 60 * 60 * 1000;

function saveState(state) {
  localStorage.setItem(STORAGE_KEY, JSON.stringify({
    savedAt: Date.now(),
    state: state,
  }));
}

function loadState() {
  const raw = localStorage.getItem(STORAGE_KEY);
  if (!raw) return null;
  const { savedAt, state } = JSON.parse(raw);
  if (Date.now() - savedAt > ONE_DAY_MS) {
    localStorage.removeItem(STORAGE_KEY);
    return null;
  }
  return state;
}
```

#### クラウド保存 (GAS経由でスプレッドシート)

- **保存タイミング**: 確定系のボタン押下時のみ
  - 1ページ目「ゲーム開始」
  - 2ページ目「得点確定」(局追加ごと)
  - 3ページ目「金額確定」(場代/飲み代それぞれ)
- **保存方式**: 毎回シート全体を上書き(累積データの整合性を保つため)
- **失敗時**: localStorage には残っているので、リトライ可能な状態に戻す

### 同期機能 (スプレッドからの読み込み)

スプレッドシート側で直接修正することがあるため、その内容をアプリ側に反映する手段を用意する。

- **同期ボタン**を画面上に常時配置(2ページ目・3ページ目どちらでも押せる位置)
- 押下時の動作:
  1. GASに読み込みリクエスト(`GET` or `action: 'load'` のPOST)
  2. スプレッドの現在の内容をパースしてstateに復元
  3. localStorageにも保存
  4. 表示を最新に更新
- レジュームで使う「state復元」と同じロジックを使い回せる
- 確認ダイアログ: ローカルの未送信変更を上書きする可能性があるため「同期しますか?」を出す

### レジューム機能

- アプリ起動時に localStorage を確認
- 未完了データがあれば「続きから再開しますか?」のダイアログを表示
  - 「はい」→ 保存された状態を復元して該当ページを表示
  - 「いいえ」→ localStorage をクリアして1ページ目から開始
- 「未完了」の判定は、最終確定フラグの有無で行う

### 状態に追加するフィールド

```js
const state = {
  // ...既存フィールド
  currentPage: 2,           // 現在のページ番号 (1/2/3)
  phase: 'venue',           // 'venue' | 'drink' (3ページ目内のモード)
  finalized: false,         // 最終確定済みかどうか
  spreadsheetId: '1abc...', // 当日のスプレッドシートID(create時に取得)
  sheetUrl: 'https://...',  // 当日のスプレッドシートURL
};
```

## 10. 実装上の注意

- iPhone Safari前提のため、表は `table-responsive` で横スクロール可能に
- 数値入力は `inputmode="numeric"` を指定してテンキー表示
- 局数は可変(最低1局〜上限なし)、追加削除に対応
- 入力途中での誤操作を防ぐため、確定操作には確認を入れるとよい(必須ではない)
- スプレッドシート書き込み中はローディング表示
- 通信失敗時はリトライ可能な状態に戻す(入力データを失わない)
